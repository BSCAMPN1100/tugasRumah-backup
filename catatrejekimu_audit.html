  • ▼ 📁 CATATREZEKIMU
    • ▼ 🔴 01 — FOUNDATION / ATURAN DASAR
      • › 01.01 — Tentukan Scope Aplikasi WAJIB
        Masalah:
        Jangan sampai aplikasi berkembang terlalu luas sebelum fitur utama selesai.
        FIX → Fokus pada toko sembako kecil/menengah: stok + penjualan + keuntungan + role Pemilik/Kasir.
      • › 01.02 — Tentukan Role Pengguna WAJIB
        Role:
        1. Pemilik/Admin
        2. Kasir
        FIX → Tentukan dengan jelas fitur apa yang boleh dan tidak boleh digunakan setiap role.
      • › 01.03 — Tentukan Aturan Harga Modal KRITIS
        Aturan yang disarankan:
        Harga modal pada saat transaksi harus disimpan bersama transaksi tersebut.
        FIX → Jangan menghitung ulang transaksi lama menggunakan harga modal terbaru.
      • › 01.04 — Tentukan Aturan Stok KRITIS
        Aturan minimal:
        Stok tidak boleh menjadi negatif.
        FIX → Jika jumlah penjualan melebihi stok, transaksi harus ditolak.
    • ▼ 🔴 02 — REQUIREMENTS
      • › 02.01 — Functional Requirements
        Tentukan fungsi sistem secara jelas.
        Contoh → Login, produk, stok, transaksi, laporan, pengguna, logout.
      • › 02.02 — Non-Functional Requirements
        Tentukan kualitas sistem.
        Contoh → offline, cepat, mudah digunakan, data tersimpan secara lokal.
      • › 02.03 — Definisi Hak Akses
        Buat tabel hak akses Pemilik dan Kasir.
        Tujuan → mencegah kasir mengubah data penting seperti harga modal dan laporan.
    • ▼ 🔴 03 — FLOW & BUSINESS LOGIC
      • › 03.01 — Flow Login
        Login → Validasi → Cek Role → Dashboard yang sesuai.
      • › 03.02 — Flow Transaksi
        Cari produk → jumlah → cek stok → keranjang → pembayaran → simpan transaksi → kurangi stok.
      • › 03.03 — Flow Kelola Produk
        Tambah → validasi → simpan.
        Edit → validasi → update.
        Nonaktifkan → konfirmasi → update status.
      • › 03.04 — Flow Laporan
        Pilih periode → ambil transaksi → hitung penjualan → hitung keuntungan → tampilkan laporan.
      • › 03.05 — Edge Cases
        Tentukan apa yang terjadi ketika:

        • Stok = 0
        • Stok tidak cukup
        • Pembayaran kurang
        • Produk tidak ditemukan
        • Username/password salah
        • Data kosong
        • Transaksi gagal disimpan
    • ▼ 🟠 04 — DATABASE / DATA MODEL
      • › 04.01 — User
        Data pengguna dan role.
      • › 04.02 — Product
        Nama produk, stok, harga modal, harga jual, status produk.
      • › 04.03 — Transaction
        Tanggal, kasir, total, pembayaran, kembalian dan informasi transaksi.
      • › 04.04 — Transaction Detail
        Produk, jumlah, harga jual saat transaksi, harga modal saat transaksi, subtotal dan keuntungan.
    • ▼ 🟠 05 — BASIC SECURITY
      • › 05.01 — Login Validation
        Username/password wajib divalidasi.
      • › 05.02 — Role Authorization
        User hanya boleh mengakses fitur sesuai role.
      • › 05.03 — Input Validation
        Validasi nama produk, harga, stok, jumlah transaksi dan pembayaran.
    • ▼ 🟡 06 — UI / UX
      • › 06.01 — Navigasi Sederhana
        Karena target pengguna dapat berasal dari pengguna non-teknologi, navigasi harus sederhana dan konsisten.
      • › 06.02 — Feedback
        Berikan feedback setelah aksi: berhasil, gagal, stok tidak cukup, pembayaran kurang, dan sebagainya.
      • › 06.03 — Accessibility Dasar
        Ukuran teks cukup besar, tombol mudah ditekan, warna tidak menjadi satu-satunya indikator.
    • ▼ 🟡 07 — TESTING
      • › 07.01 — Test Login
      • › 07.02 — Test Transaksi
      • › 07.03 — Test Stok
      • › 07.04 — Test Perhitungan Keuntungan
    • ▼ 🟢 08 — NICE TO HAVE

      • › 08.02 — Backup Database
